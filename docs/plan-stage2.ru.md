# Этап 2: поведение и дизайн

Пользователь поручил продолжать разработку по существующему ТЗ.
Выполнение последовательно в текущем изолированном каталоге, без
публикации и автоматической активации Home Manager профиля.

## Шаг 2.1 — Dock и настройки, версия 0.2.0

1. `dock_model.rs`: проверяемые правила autohide (150/700 мс), menu/drag/
   keyboard holds, fullscreen и explicit reveal; gaussian zoom до 1.45,
   reduced motion; стабильная геометрия, переполнение и reorder pins;
   generation tokens для launch timeout. Сначала RED unit tests.
2. `settings.rs`: schema 2, миграция schema 1 с backup перед записью,
   строгая валидация диапазонов и typed partial patch; pins не теряются.
   Проверить read-only Nix symlink, conflicts и malformed patches.
3. `zoom_icon.rs`, `dock.rs`: собственный GTK snapshot widget; фиксированная
   layout/hit geometry, конечный frame callback без redraw в покое;
   узкая layer edge surface для autohide, input region без прозрачных
   полей, overflow scroll, drag/reorder, клавиатурный reveal/Escape.
4. UI: сохранение идентичности кнопок при обновлении окон, актуальные
   handles в callbacks, dark/light/system темы и reduced motion, реальные
   базовые настройки с применением без перезапуска. GTK4 4.20 API
   используется с уже закреплённой GTK 4.22.5 для system color preference.
5. D-Bus GetConfig/ValidatePatch/ApplyPatch/GetDockState/ReorderPin/Reload,
   bounded запросы и машинные errors; CLI config/reorder/reload.
6. Nix: те же три ELF и runner, Home Manager schema 2. Сохранить
   существующие headless/scale/E2E checks и добавить проверку новых
   настроек, readonly, invalid reload, конфиг migration, стабильность
   Dock при обновлении окон. Затем release и outputs/stage-2.1.

## Ближайший шаг после 2.2.3 — карточки и клики Dock

По просьбе пользователя уточняется D04. Наведение открывает карточки окон
в порядке их обнаружения. Карточка активирует своё окно. Первый клик по
неактивной группе восстанавливает первое окно, следующие клики переходят
к следующим окнам, клик по последнему активному окну сворачивает его.
Для одного окна это обычное переключение между активацией и сворачиванием.

1. 2.2.4 / 0.2.4: карточки с заголовком, иконкой и состоянием, стабильный
   порядок кликов и тест в отдельном Labwc. Существующий переключатель
   сворачивания сохраняется, его значение по умолчанию становится true.
2. Настоящие изображения отдельных окон: проверить compositor с
   ext_foreign_toplevel_image_capture_source_manager_v1 и надёжную связь
   capture handle с управляемым окном. Labwc 0.9.7 из текущего flake
   публикует только источник захвата экрана. При недоступном capture
   оставить карточку с метаданными. Не сохранять кадры на диск.
3. Продолжение плана этапа 2: календарь, overflow, порядок панели,
   размещение окон на экране вызова и оставшиеся возможности Dock.

### Ограничения при возобновлении сборки

18 ноября 2026 в 14:08 по Якутску ядро зафиксировало системный OOM.
В это время Nix запустил проверку Cargo с `-j 32`, параллельно шла
локальная проверка. Полный релиз 0.2.4 прерван. Перед возобновлением
проверить свободную память и диск. Запускать сборку и тесты последовательно.
Для Nix использовать `--max-jobs 1 --cores 2`, для локального Cargo
`CARGO_BUILD_JOBS=2`. Начать с точечного теста карточек и не запускать
проверки в пользовательском графическом сеансе.

## Шаг 2.2.5 — часы и календарь панели

Захват изображений остаётся отдельной задачей. Labwc 0.20.0 добавляет
захват через ext-foreign-toplevel, а управление окнами использует
wlr-foreign-toplevel-management. Нужна надёжная связь между объектами
двух протоколов. Сопоставление по заголовку и app_id неоднозначно.

Часы используют локальные дату и время. Клик открывает календарь
текущего месяца на той же панели. Доступны навигация по месяцам, выбор
дня и возврат к сегодняшней дате. Закрытие возвращает обычный режим
клавиатуры панели. Проверка в отдельном Labwc: открытие мышью, переход
на другой месяц, Escape и повторное открытие на сегодняшней дате.
