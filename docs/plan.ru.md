# План реализации mosaic-shell

Основание: `spec.ru.md`, пользователь поручил начать разработку 17.11.2026.
Выполнение последовательно в текущем отдельном каталоге, без публикации,
изменения NixOS и остановки существующих компонентов рабочего стола.

## Этап 0: проверка платформы

1. Создать `shellctl doctor`: Rust, read-only диагностика, без сторонних crates.
   `wayland.rs` читает registry через отдельное Unix-соединение; этот
   адаптер предназначен только для диагностики, не для GTK/window management.
   `doctor.rs` проверяет обязательные globals и владельцев D-Bus,
   `process.rs` ограничивает время и объём вывода дочерних процессов.
2. Тестами проверить повреждённые/обрезанные сообщения, UTF-8, порядок байтов,
   EOF, лимиты, таймауты, четыре состояния интеграций, exit codes CLI.
3. Снять реальные версии, globals, GPU и службы. Не подменять проверку
   действий наличием протокола. Изолированный GTK layer-shell прототип
   собрать отдельно, не устанавливать его в сессию автоматически.
4. Зафиксировать матрицу рисков, результаты и блокеры. Этап 0 завершён
   только после проверок GTK surfaces, activate/minimize с seat bridge,
   focus, fractional scale, lifecycle, audio и lock readiness.
5. Поставить x86_64-linux бинарник, исходники, SHA256 и команду запуска.

Проверки: `cargo test --offline`, `cargo fmt --check`,
`cargo clippy --offline --all-targets -- -D warnings`, release build,
запуск release CLI на реальной сессии и при отсутствии Wayland.

## Следующие этапы (после закрытия блокирующих рисков)

1. Вертикальный срез: UI/backend/session D-Bus, каталог приложений,
   закрепления, панель/Dock, один монитор, Nix и Home Manager.
2. Поведение и дизайн: собственный Dock, анимации, темы, autohide,
   несколько мониторов, hotplug, tray, настройки.
3. Системные компоненты: службы, control center, уведомления, lock/power.
4. Полнота: launcher, app grid, файловый менеджер и поиск, фон, desktop menu, GUI.
5. Приёмка A01–A18, доступность, профилирование, документация, выпуск.

Каждый этап имеет отдельный каталог поставки с бинарниками и командой
запуска. Незавершённые проверки явно отмечаются; номер этапа не означает
готовность полной оболочки. Конкретные планы последующих этапов уточняются
по фактическим результатам этапа 0.

Поэтапная реализация системных компонентов описана в
[плане этапа 3](plan-stage3.ru.md).

## Журнал решений

- Пользователь уже поручил выполнение приложенного плана; повторное
  согласование того же ТЗ не требуется.
- Системные библиотеки и Rust берутся из доступного nixpkgs; обновление
  системы не выполняется. Основной UI сохранит GTK4/gtk4-layer-shell.
- Отдельная диагностика registry не передаёт объекты в GTK.
- Лицензия собственного кода остаётся нерешённой до публикации.

## Этап 4: файловый менеджер Mosaic

Отдельное приложение GTK4 с привычной моделью навигации Windows Explorer
и собственным оформлением Mosaic. Первая поставка Mosaic Files сделана
вместе с исправлениями шага 3.13. Она включает боковые места, вкладки с
независимой историей, адресную строку, список с колонками, фильтр текущей
папки и базовые файловые операции. Пункты ниже описывают полный объём
этапа 4.

1. Навигация: боковая панель с домашней папкой, избранным, недавними
   местами и доступными томами. Вкладки, история назад/вперёд, переход
   вверх и адресная строка с сегментами пути и вводом полного адреса.
2. Содержимое папки: список с колонками имени, типа, размера и даты,
   сетка значков, сортировка, выделение нескольких файлов, поиск в папке.
   Операции чтения каталогов и поиска идут асинхронно и отменяются при
   смене папки. Большие каталоги не должны блокировать окно.
3. Операции через GIO: открыть, создать папку, переименовать, копировать,
   переместить и отправить в корзину. Показывать ход работы, ошибки и
   выбор при конфликте имён. Удаление без корзины требует отдельного
   подтверждения. Учитывать права доступа и тома только для чтения.
4. Интеграция: отдельный бинарник и desktop entry. Кнопка домашней папки
   в меню Mosaic, запуск из Dock и из поиска. Выбор менеджера по
   умолчанию оставляется пользователю.
5. Приёмка в временных каталогах: клавиатурная навигация, вкладки,
   сортировка, большие каталоги, конфликты имён, отмена, отсутствие прав
   и отключение тома. Поставка бинарника, исходников и команды запуска.

### Шаг 4.1. Копирование и перемещение между вкладками

1. Проверить перенос локального файла и копирование папки с символической
   ссылкой во временных каталогах. Отдельно проверить конфликт имени
   и запрет копирования папки внутрь самой себя.
2. Добавить общий для вкладок буфер на один выбранный объект,
   команды на панели и сочетания Ctrl+X, Ctrl+C, Ctrl+V. Операции
   выполняются в фоне. При конфликте можно оставить оба объекта.
3. Проверить операции между вкладками на виртуальном экране. Собрать
   отдельный пакет с бинарником файлового менеджера и командой запуска.

### Шаг 4.2. Колонки файлов и локальная диагностика

1. Добавить колонку «Тип» и сортировку по имени, типу, размеру и дате.
   Проверить соответствие выбранной строки операции после пересортировки.
2. Записывать диагностические события оболочки, сервиса и файлового
   менеджера в закрытый локальный каталог. Ограничить размер, добавить
   просмотр последних записей через `shellctl logs`.
3. Проверить отказ запуска и ошибки файловой операции в отдельных
   сессиях. Собрать бинарники и опубликовать команды запуска.

### Шаг 4.3. Групповое выделение и операции

1. Поддержать Ctrl+клик, Shift+клик и Ctrl+A в списке текущей папки.
   Показывать количество выделенных объектов в строке состояния.
2. Вставлять группу из общего буфера между вкладками по одному объекту.
   Сохранять ранее завершённые операции. При конфликте предлагать
   пропустить объект, сохранить оба или остановить оставшиеся операции.
   Для корзины показывать одно подтверждение с количеством объектов.
3. Проверить отмену и повторную вставку непройденной части
   после группового переноса. Собрать бинарники и команду запуска.

### Шаг 4.4. Таблица и сетка значков

1. Добавить выбор вида папки в каждой вкладке. Использовать одну
   модель для сортировки, фильтрации и выделения в таблице и сетке.
2. Сохранить открытие папок и операции с выделенными объектами в сетке.
   Проверить переключение, копирование выделения и независимость вкладок
   на виртуальном экране.
3. Собрать отдельный бинарник и опубликовать команду запуска.

### Шаг 4.5. Сегменты адреса и меню объекта

1. Показывать корень и родительские папки отдельными кнопками.
   Текстовый адрес открывать через Ctrl+L или кнопку редактирования.
2. Открывать меню действий по ПКМ над объектом в таблице и сетке.
   Сохранять группу, если выбранный объект уже входит в выделение.
   Добавить копирование пути и просмотр свойств объекта.
3. Проверить переход к родителю, отмену правки адреса и действия
   меню на виртуальном экране. Собрать бинарники и команду запуска.

### Шаг 4.6. Создание и выделение мышью

1. Добавить «Новый файл» и «Новая папка» в меню ПКМ. Создавать пустой
   файл с заданным именем. При совпадении имени сохранить старый объект.
2. Выделять созданный объект после обновления списка. Поддержать
   рамку мышью в таблице и сетке вместе с Ctrl и Shift.
3. Проверить пустую папку, меню объекта и рамку на виртуальном экране.

### Шаг 4.7. Группы Dock, пользовательские иконки и настройки наведения

1. Разделить закреплённые и запущенные незакреплённые приложения.
   Проверить горизонтальный и вертикальный Dock и работу перетаскивания.
2. Добавить выбор локальной PNG-иконки и сброс через меню приложения.

3. Настраивать силу и радиус увеличения, длительность увеличения и
   возврата, кривую анимации, включение карточек и их задержки.
4. На Labwc 0.9.7 показывать карточки в форме окон с пометкой, что
   содержимое недоступно. Захват отдельных окон остаётся в плане до
   совместимой версии композитора и надёжного сопоставления окон.

### Шаг 4.8. Миниатюры содержимого окон

1. Сопоставлять окна управления и захвата только при однозначном
   совпадении `app_id` и заголовка в обоих списках Wayland.
2. Получать миниатюры через `grim -T`, пока карточки открыты. Ограничить
   параллельность, время захвата и размер изображения, хранить кадр в памяти.
3. Проверить реальные кадры на Labwc 0.20 и карточки без кадра на 0.9.7.

### Шаг 4.9. Закреплённые папки и доступ администратора в Mosaic Files

1. Добавить «Закреплённые» слева, действия закрепления и открепления

2. Для локальных файлов и папок запрашивать административный доступ
   через GVfs и Polkit по явному действию. Открывать защищённые текстовые
   файлы во встроенном редакторе, проверять конфликт при сохранении.
3. Проверить обычное открытие, сохранение закреплений и работу без

4. Убрать повторяющийся текст из карточек без изображения и проверить
   отображение живых миниатюр на совместимом Labwc.

### Шаг 4.10. Датчики температуры

Читать `hwmon` и `thermal` без записи в sysfs, показывать показания и
состояния датчиков в центре управления. Добавить независимый индикатор

открыта страница или виден индикатор. Спящие устройства не опрашиваются
на чтение температуры, если ядро явно сообщает о приостановке `hwmon`.

### Шаг 4.11. Питание и профили

Добавить страницу питания и кнопку верхней панели. Показывать заряд,
источник питания, состояние и расчётное время, когда UPower их сообщает.

состояния службы. Проверить отказ, пропажу службы и смену её владельца.

## Расширения системных настроек и рабочего стола

На этапе 3 расширяются модули центра управления:

- Wi-Fi через NetworkManager: выбор адаптера, обновление списка сетей,
  уровень сигнала, подключение к сохранённым сетям и WPA-Personal,
  отключение, удаление сохранённого профиля с подтверждением. Пароли
  обрабатывает агент NetworkManager. Сложные профили открываются во внешнем
  редакторе.
- Bluetooth через BlueZ: выбор и питание адаптера, поиск устройств,
  сопряжение с подтверждением, подключение, отключение и удаление устройства.
  Показывать состояние и заряд, когда BlueZ его предоставляет.
- Детальный звук через PulseAudio API, включая PipeWire с pipewire-pulse:
  входы и выходы, порты и поддерживаемые профили, баланс каналов, уровень
  микрофона, громкость и mute отдельных приложений, перенос потоков между
  устройствами. Подтверждённое состояние обновляется по событиям сервера.
- Температуры и необязательный индикатор CPU/GPU реализованы в шаге 4.10.

На этапе 4 модуль обоев получает локальные анимированные источники:
видео и поддерживаемые анимированные изображения. На каждый монитор
можно выбрать источник, масштабирование, зацикливание и FPS. Останавливать
декодирование при скрытии обоев или отключении монитора. Учитывать режим
уменьшения анимации и иметь статический кадр для недоступного декодера.
Проверить нагрузку CPU/GPU и память отдельно от функциональных тестов.

Для каждого модуля предусмотрены проверка отказов и отсутствующих
служб, изолированные тесты и отдельная поставка в порядке этапов.
