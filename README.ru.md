# Mosaic 0.4.10 — питание и профили (шаг 4.11)

Rust/GTK4 оболочка для NixOS/Labwc: верхняя панель, плавающий Dock,
каталог приложений, запуск через GIO, обнаружение и управление окнами,
закрепления, CLI и D-Bus backend. В пакет также входит первая версия
файлового менеджера Mosaic Files.

## Запуск собранного пакета

[Что подключить в NixOS](docs/nixos-requirements.ru.md).

В обычном терминале вашей Labwc-сессии:

```sh
./mosaic-session
```

У закреплений Dock меняется порядок перетаскиванием к краю другой
иконки. Контекстное меню закрепления содержит перемещение в обе стороны
и открепление. В «Настройки → Панель» включаются отдельные кнопки Wi-Fi,
Bluetooth, яркости, звука, оформления и Dock.

Закреплённые приложения и открытые незакреплённые приложения разделены
линией. Через ПКМ по значку можно выбрать PNG и вернуть стандартную иконку.
Настройки Dock содержат силу и радиус увеличения, длительности увеличения
и возврата, кривую, включение карточек и задержки открытия и закрытия.

В центре управления появилась страница «Температуры». Индикатор CPU и
GPU включается отдельно в «Настройки → Панель». Для вывода без оболочки
используйте `./shellctl temperatures status`.
Живые миниатюры обновляются, пока карточка видна. Захват использует
Wayland-протоколы отдельных окон (Labwc 0.20 и новее). На Labwc 0.9.7
и для окон с неоднозначными заголовками видны заголовок, значок и состояние.

Для Labwc 0.9.7 поставляется профиль переключателя с миниатюрами.
Команда записывает пользовательский `rc.xml`; при наличии редактируемого
файла делает его резервную копию. Если такого файла ещё нет, берёт текущую
системную конфигурацию за основу. Сама команда Labwc не перезапускает.
Примените её и перечитайте конфигурацию в своей Labwc-сессии:

```sh
./mosaic-alt-tab --apply
labwc --reconfigure
```

Alt+Tab перебирает окна в порядке недавнего фокуса. Shift+Alt+Tab
двигается в обратную сторону. Отпускание Alt подтверждает выбор.
Escape отменяет его.

```sh
./mosaic-files
./mosaic-files ~/Downloads
```

В Mosaic Files работают Ctrl+L для адреса, Ctrl+T и Ctrl+W для вкладок,
Alt+← и Alt+→ для истории, Alt+↑ для перехода вверх, Ctrl+F для фильтра
текущей папки и Ctrl+Shift+N для создания папки.

Путь состоит из кнопок папок. Например, кнопка `home` в
`/home/user` открывает `/home`. Ctrl+L или кнопка с карандашом
открывают текстовый ввод. Enter применяет введённый путь, Escape
закрывает ввод. Правый клик по строке или значку открывает действия,
включая «Копировать путь» и «Свойства». Правый клик внутри группы
сохраняет её выделение.

ПКМ на свободном месте показывает «Новый файл…» и «Новая папка…».
Укажите полное имя
файла с нужным расширением. Файл создаётся пустым. Если имя занято,
содержимое существующего файла сохраняется.

ПКМ по папке → «Закрепить папку слева» добавляет её в «Закреплённые».
Ctrl+D закрепляет или открепляет текущую папку. Список сохраняется после
закрытия приложения.

«Открыть с правами администратора…» в меню локального файла или папки
передаёт запрос системе через GVfs и Polkit. Встроенный редактор открывает
текст UTF-8 до 1 МиБ и проверяет, менялся ли файл с момента открытия.

В таблице и сетке выделяйте файлы и папки рамкой, удерживая левую кнопку
мыши. Созданный объект сразу выделяется, если он виден в текущем списке.

Ctrl+клик добавляет или снимает выделение, Shift+клик выделяет диапазон,
Ctrl+A выделяет все отображаемые объекты. В списке файлов Ctrl+C,
Ctrl+X и Ctrl+V работают с группой. Внутренний буфер общий для вкладок.
При конфликте можно сохранить оба объекта, пропустить конфликтующий
или остановить вставку. Уже перенесённые объекты остаются на месте,
остальные можно вставить повторно. Корзина запрашивает одно подтверждение
с количеством объектов. Копирование работает между локальными папками,
перенос поддерживается внутри одной файловой системы.

Заголовки «Имя», «Тип», «Размер» и «Изменён» меняют порядок
сортировки. Повторный клик меняет направление. Папки остаются сверху.
Выбор справа от поиска переключает таблицу и сетку. С клавиатуры
работают Ctrl+1 и Ctrl+2 соответственно. Вид сохраняется в текущей
вкладке до её закрытия. Выделение, фильтр и порядок сортировки
переходят между таблицей и сеткой.

## Диагностика

```sh
./shellctl logs
./shellctl logs --path
```

Журнал доступен и после завершения Mosaic. Он хранится в
`$XDG_STATE_HOME/mosaic`, по умолчанию `~/.local/state/mosaic`.
Хранятся два файла по 128 КиБ. Команда показывает 80 последних записей.
В каждой строке есть время в миллисекундах Unix, версия, PID, компонент,
событие и числовой код. Тексты ошибок, имена файлов, пути, SSID и пароли
в этот журнал не записываются. При запуске через `mosaic-session`
записывается также код завершения оболочки. Для сбоя всей системы
дополнительные сведения могут быть в системном журнале.

Скрипт запускает `mosaic-services` и `mosaic-shell` отдельно от группы
процессов терминала. Ctrl+C останавливает оболочку и её backend.
Приложения, открытые через Mosaic, остаются запущенными.

```sh
./shellctl applications
./shellctl control-center
./shellctl wifi show
./shellctl wifi status
./shellctl bluetooth show
./shellctl bluetooth status
./shellctl brightness show
./shellctl brightness status
./shellctl audio status
./shellctl settings
./shellctl windows
./shellctl quit
```

Кнопка слева от часов открывает центр управления на этой панели.
Тема и параметр «Уменьшить движение» применяются сразу и сохраняются
в общей конфигурации. При декларативном управлении значения доступны
для просмотра. Повторный вызов на том же мониторе или Escape закрывает
центр. Команда `shellctl control-center [OUTPUT]` принимает имя монитора.
Если этот монитор недоступен, используются обычные правила выбора экрана.

Кнопка «Яркость» в Центре управления открывает регулировку подсветки
встроенного дисплея. Ползунок от 1 до 100 процентов работает, когда
ядро предоставляет устройство backlight и logind разрешает действие
в активной локальной сессии. После изменений с клавиш яркости Mosaic
показывает фактический уровень.

Кнопка «Bluetooth» в заголовке Центра управления открывает страницу BlueZ.
Выберите адаптер, чтобы включить или выключить его и увидеть устройства.
«Найти устройства» запускает поиск на 15 секунд. «Остановить поиск»
завершает сессию Mosaic сразу. Список показывает состояние сопряжения,
подключение и заряд, когда BlueZ его сообщает.
Для агента сопряжения запустите `MOSAIC_BLUETOOTH_PAIRING=1 ./mosaic-session`
или включите `programs.mosaic-shell.bluetoothPairing.enable` в Home Manager.
Рядом с новым устройством нажмите «Сопрячь». Страница покажет код
для сверки, код для ввода на устройстве или поле ввода PIN, когда
BlueZ запросит подтверждение. Для сопряжённых устройств доступны
подключение, отключение и удаление. Чтобы удалить сохранённое сопряжение,
подтвердите имя и адрес устройства.

Кнопка «Wi-Fi» в заголовке Центра управления открывает список сетей
через NetworkManager. Выберите адаптер и нажмите «Обновить», чтобы
запустить сканирование. В списке показаны сигнал, тип защиты и
текущее подключение. Кнопка «Подключить» использует совместимый
сохранённый профиль NetworkManager. Для новой сети WPA2/WPA3-Personal
после «Подключить» нажмите «Создать профиль». Пароль запрашивает
запущенный в сессии агент секретов NetworkManager. Если NetworkManager
сообщит об отсутствии пароля, Mosaic покажет это в статусе подключения.
Кнопка «Отключить» завершает текущее подключение выбранного адаптера.

Кнопка «Профили» открывает список сохранённых настроек Wi-Fi, включая сети
вне зоны видимости. «Изменить…» открывает выбранный профиль, а «Внешний
редактор» открывает общий список для добавления и настройки подключений.
Для этих двух действий нужен установленный `nm-connection-editor`. После
замены настроек в редакторе нажмите «Обновить» в Mosaic.
При удалении Mosaic запрашивает подтверждение. Удаление активного профиля
прерывает его подключение.

Раздел «Звук» позволяет выбрать стандартные вход и выход, менять
громкость выхода и отключать звук на обоих устройствах. Состояние
обновляется по событиям. Для подключения используется `PULSE_SERVER`
или сокет `$XDG_RUNTIME_DIR/pulse/native`. На PipeWire эту совместимость
предоставляет работающий `pipewire-pulse`. При отсутствии сервера раздел
показывает, что звук недоступен, и повторяет подключение.

Во вкладке «Устройства» ползунок «Уровень входа» меняет уровень
выбранного микрофона или другого входа с сохранением отключения звука.
«Баланс выхода» доступен для стереоустройства с ненулевой громкостью.
Он перераспределяет уровень между левым и правым каналами, сохраняя
громкость более громкого канала.

Вкладка «Профили и порты» показывает режимы звуковых карт и порты
выбранных входа и выхода. Набор зависит от устройства и текущего
профиля. После переключения список устройств обновляется по событиям
аудиосервера. Вкладка появляется, если сервер сообщает профили или порты.

В разделе «Звук» вкладка «Приложения» показывает активные
потоки воспроизведения. У каждого есть свой выход, громкость и переключатель
«Без звука». Например, музыку можно отправить в наушники, а звук игры
оставить на колонках. Если приложение воспроизводит несколько потоков,
для каждого доступна отдельная строка. Запуск новых потоков следует
настройкам аудиосервера.

Кнопка Mosaic открывает каталог с поиском по названию. Клик по значку Dock запускает приложение без окон. Для открытых окон
клики переходят от первого к последнему, затем сворачивают последнее.
При наведении появляются карточки окон. Клик по карточке активирует окно.
В Labwc 0.9.7 карточки показывают иконку, заголовок и состояние. Захват
изображения отдельного окна требует поддержки протокола композитором.
Новые настройки включают сворачивание повторным кликом по умолчанию.
Сохранённое значение dock.minimize_on_click=false сохраняет свой эффект. Правый клик даёт список окон,
повторный запуск и закрепление/открепление. Точка означает запущенное
приложение, рамка — активное, кольцо — ожидающий запуск.

CLI `windows` выводит epoch, ID, app_id, active/minimized без заголовков.
Команды `window activate|minimize|close EPOCH ID` адресуют конкретное окно.
`launch DESKTOP_ID`, `pin DESKTOP_ID`, `unpin DESKTOP_ID` — асинхронные
запросы UI. Код 0 означает принятие, состояние подтверждается событиями.
`doctor` остаётся доступен для проверки платформы.

## Конфигурация

`$XDG_CONFIG_HOME/mosaic-shell/config.toml`, по умолчанию
`~/.config/mosaic-shell/config.toml`:

```toml
schema_version = 2
revision = 0
pins = ["firefox.desktop", "org.xfce.Thunar.desktop"]
```

При сохранении revision увеличивается; файл заменяется атомарно с
правами 0600. Неизвестные поля и версия отклоняются. Symlink-конфигурация,
включая Nix-файл, не переписывается; редактирование в GUI отключено.
При невалидном startup config UI использует встроенные значения и
показывает ошибку; сохранение поверх невалидного файла отклоняется.
Схема 1 мигрирует в памяти; перед первой записью схемы 2 создаётся
`config.toml.v1.bak`. Для отката остановите оболочку и восстановите копию.
При возврате на 0.2.6 восстановите файл, сохранённый до 0.2.7,
или удалите раздел `[panel]` из конфигурации.
При возврате на 0.2.8 восстановите старый файл или удалите строку
`edge = ...` из раздела `[dock]`.
Для отката на 0.2.10 также можно удалить строку `current_output_only = ...`
из раздела `[dock]`.
При откате на 0.2.11 удалите строку `all_outputs = ...` из того же раздела
или восстановите прежний файл.

Настройки применяются сразу через GUI или CLI:

```sh
./shellctl config get
./shellctl config set 'dock.auto_hide=true'
./shellctl config set 'theme.mode="light"'
./shellctl reorder firefox.desktop org.xfce.Thunar.desktop
./shellctl reload
./shellctl dock state
```

Параметры: `theme.mode` dark/light/system; `general.reduced_motion`;
`dock.preferred_output` (connector, пустая строка — авто);
`dock.icon_size` 32..80; `dock.magnification`, `dock.auto_hide`,
`dock.show_delay_ms` 0..2000 (по умолчанию 150), `dock.hide_delay_ms`
100..5000 (700), `dock.minimize_on_click`. System следует настройке GTK,
при её отсутствии используется тёмная тема. Reduced motion и системное
отключение анимации отключают увеличение. Меню/drag удерживают Dock;
в fullscreen он скрыт, `shellctl dock show` вызывает его, Escape
освобождает клавиатуру. Перетаскивание меняет порядок закреплений.

В разделе «Dock» параметр «Расширение фона, %» задаёт рост
фона к центру экрана. `dock.hover.background_percent` принимает
0..25, по умолчанию 12. Ноль отключает расширение фона.

`reload` перечитывает файл явно, автоматического наблюдения пока нет.
Невалидный reload сохраняет рабочую конфигурацию. D-Bus ApplyPatch и
ReorderPin проверяют ожидаемую revision; CLI читает её перед изменением.

## Nix / Home Manager

Сборка из каталога исходников:

```sh
nix build "path:$PWD"
./result/bin/mosaic-session
nix flake check "path:$PWD"
```

Flake экспортирует `homeManagerModules.default`. Добавьте его в свои
Home Manager imports и включите:

```nix
programs.mosaic-shell = {
  enable = true;
  # Необязательно: декларативные pins, изменения через GUI отключены.
  settings.pins = [ "firefox.desktop" "org.xfce.Thunar.desktop" ];
};
```

Проверяемая среда: UWSM с активным `graphical-session.target` и
импортированной Wayland-средой. Target `mosaic-session.target` привязан
к graphical-session; UI/backend имеют PartOf/BindsTo, restart-on-failure
и ограничение restart bursts. После установки войдите в сессию заново
либо запустите `systemctl --user start mosaic-session.target`.

Остановка: `systemctl --user stop mosaic-session.target`. Для удаления
сначала остановите target, затем задайте enable=false и примените свой
Home Manager. У текущего пользователя модуль автоматически не применялся.
Для Labwc без UWSM lifecycle hook пока требуется отдельная интеграция.

## Проверки и зависимости

Закреплены Cargo.lock, Rust 1.95.0 и flake.lock. Проверены Labwc 0.9.7,
GTK4 4.22.5, gtk4-layer-shell 1.3.0. Более ранние Labwc не заявляются.
Production код использует gtk4-rs, wayland-client и zbus; unsafe запрещён.
Низкоуровневые FFI-файлы в `probes/` — отдельные тестовые fixtures.

```sh
nix develop "path:$PWD"
cargo test --features desktop
cargo fmt --check
cargo clippy --features desktop --all-targets -- -D warnings
```

Flake checks: Rust tests/fmt/clippy, headless scales 100/125/150/200%,
изолированный D-Bus + реальный GIO launch, minimize/activate/close,
устаревшие IDs/epoch, pins, restart UI, duplicate instances, сборка
тестовой Home Manager generation без её активации.

## Границы этапа

Добавлены zoom до 1.45 без изменения layout, autohide, drag/reorder,
три режима темы и GUI настроек. Панель на каждом подключённом мониторе,
по умолчанию один Dock на `dock.preferred_output`. Без preferred или при его отсутствии
выбирается первый доступный connector в лексикографическом порядке.
Порядковый индекс GDK не сохраняется. При отсутствии connector выход
используется только временно, явная постоянная привязка к нему недоступна.
`outputs` показывает connector, manufacturer/model/description, geometry,
scale и mapped surfaces; `window-outputs` — реальные enter/leave членства.
При отключении выхода закрывается привязанное к нему окно, Dock переносится,
pins и preferred не теряются. При возврате preferred Dock возвращается.
Ноль выходов скрывает поверхности; подключение восстанавливает их.
Fullscreen активного окна скрывает только панель/Dock его выхода.

```sh
./shellctl outputs
./shellctl window-outputs
./shellctl config set 'dock.preferred_output="DP-4"'
```

Поле экрана в GUI принимает connector, Enter применяет его. Поиск
приложений и настройки открываются на мониторе кнопки. Вызов из CLI
использует экран активного окна и затем предпочитаемый выход Dock.
Можно явно указать монитор поиска через `./shellctl launcher DP-4`.
Escape или кнопка в заголовке закрывает окно. Команды
`./shellctl dialog state` и `./shellctl dialog close` показывают
состояние диалога и закрывают его. Окно оболочки использует layer-shell
и не входит в список обычных окон Wayland.
По умолчанию Dock показывает окна всех мониторов. В настройках
«Окна только на экране Dock» включает фильтр по событиям Wayland.
Закрепления остаются доступны для запуска. Фильтр учитывается в
индикаторах, карточках, меню и цикле активации. Приложение с окнами на
нескольких мониторах появляется на выбранном экране, если у него есть
хотя бы одно окно на этом экране. Окна без подтверждённого монитора
появляются при выключенном фильтре.

```sh
./shellctl config set 'dock.current_output_only=true'
```

Переключатель «Dock на каждом мониторе» включает отдельный Dock
на каждом подключённом выходе. Закрепления общие. Автоскрытие, карточки
и полноэкранный режим работают отдельно для каждого выхода. При включённом
фильтре окон каждый Dock использует свой экран.

```sh
./shellctl config set 'dock.all_outputs=true'
./shellctl dock show DP-4
./shellctl dock state DP-4
./shellctl dock cards DP-4
```

Без аргумента команды Dock обращаются к основному выходу.
Уведомления, системные модули центра управления и фон входят в следующие шаги.
`mosaic-services` объявляет health и tray-sni; не занимает
имя сервера уведомлений и не заменяет mako/dunst.

Каталог сейчас строится при старте UI; перенос индексации в backend и
проверка поиска на 2000 приложений относятся к дальнейшей реализации.
Известные небольшие ограничения: revision не защищает от одновременной
записи внешним редактором между проверкой и rename. Повторный запуск
имеет отдельный token, старый timeout не снимает новый indicator.
Часть функций ТЗ, включая desktop actions, пока не реализована.

ELF-файлы используют Nix store этой сборки. На другой машине соберите flake
или импортируйте готовый пакет из GitHub Actions.

Dock checks используют виртуальный указатель только в собственном
headless compositor на масштабах 100/125/150/200%: zoom и отсутствие
кадров в покое, edge reveal, menu/drag holds, реальный reorder, fullscreen,
ошибки config/reload/read-only и конфликты revision.

Multi-output Nix check: два headless выхода с разными масштабами и
отрицательным расположением, preferred fallback/reconnect, zero outputs,
сохранение pins, popup closure, scoped fullscreen и изменение scale.
Это проверка Wayland lifecycle; реальный DRM hotplug ещё требует приёмки.

## Системный трей SNI

Backend обслуживает KDE/freedesktop StatusNotifierWatcher/Host. При уже
занятом имени watcher регистрируется host и импортируется существующий
список, без вытеснения чужого watcher. Один элемент может иметь несколько
регистраций: удаление одной не удаляет остальные. Привязка действий — к
уникальному владельцу D-Bus и object path, не к переиспользуемому alias.

На всех панелях показываются Active/NeedsAttention, Passive скрыт.
Предпочитается известный значок темы, затем RGBA texture из SNI pixmap,
затем placeholder. Tooltip — обычный текст, markup не выполняется.
Левый клик — Activate, средний — SecondaryActivate; правый клик и
ItemIsMenu открывают DBusMenu, если приложение экспортирует Menu. Колесо передаёт
Scroll с направлением и дельтой 120 на шаг. Глобальные координаты Wayland
не угадываются: собственное меню привязано к значку. Если Menu отсутствует,
используется SNI ContextMenu с fallback 0,0 и размещением у приложения.

```sh
./shellctl tray state
./shellctl tray snapshot
```

UI обменивается снимками с `org.mosaic.Tray1` асинхронно; backend
перезапускается независимо, исчезновение владельца удаляет элементы.
Размеры ограничены: 128 items, pixmap до 256×256, строки до 512 символов.
Ошибки действий видны в tooltip/диагностике. Без backend показывается
признак недоступного трея. Нет polling и XEmbed. Панель вне открытого меню не захватывает клавиатуру.

IconThemePath/overlay ещё не реализованы; весь этап 2
пока не завершён. При 128 максимальных pixmap с
длинными UTF-8 строками возможен отказ UI по общему лимиту 34MB; invalid
attention pixmap пока не пробует normal pixmap. Эти minor ограничения
записаны для дальнейшего шага.

Новые Nix checks: реальные pointer actions в private compositor при своём
и внешнем watcher, restart backend, alias release, внешнее unregistration,
два источника регистрации и запоздалый ответ watcher после потери имени.
Протокол: [StatusNotifierWatcher](https://specifications.freedesktop.org/status-notifier-item/latest/status-notifier-watcher.html),
[StatusNotifierItem](https://specifications.freedesktop.org/status-notifier-item/latest/status-notifier-item.html).

## DBusMenu

Меню строится GTK на экране кнопки, без предположений о глобальном
положении указателя. Поддерживаются подменю, separator, checkmark/radio,
known icon-name, plain labels и скрытые/отключённые пункты. Состояние
переключателей задаёт приложение, оболочка не переключает их авансом.
AboutToShow вызывается перед открытием; LayoutUpdated и
ItemsPropertiesUpdated обновляют уже открытое меню. Кнопки трея сохраняют
идентичность при изменениях tooltip/статуса.

Клавиши: ↑/↓ — пункты, → — подменю, ← — назад, Enter/Space — выбор,
Escape — закрытие. Меню получает клавиатуру только пока показано;
закрытие/исчезновение выхода/владельца/backend освобождает её. Ошибка
загрузки показывается в привязанном popover, ошибка действия — в tooltip
и `tray state`. Отсутствие Menu вызывает старый ContextMenu приложения;
ошибка существующего DBusMenu не маскируется таким fallback.

```sh
./shellctl tray menu ':1.42/StatusNotifierItem'
# token и ID берутся из актуального снимка; скрытые/disabled/stale отклоняются:
./shellctl tray menu-event ':1.42/StatusNotifierItem' TOKEN ID
```

Дерево ограничено 256 nodes, глубиной 8 и 1MiB; labels до 512 символов.
Неверные типы, повтор ID и превышения отклоняются. Event адресуется только
уникальному владельцу и текущему token. При инвалидации AboutToShow может
использовать последние проверенные submenu IDs, Event — только свежий
снимок; смена Menu path очищает эти metadata IDs.

PNG icon-data, shortcuts/Alt mnemonics и RTL override ещё не реализованы.
Радио-группы и действия остаются ответственностью приложения.
Новые menu Nix checks — реальные pointer + wtype на 100/125/150/200%,
включая lazy queue, live update, ошибки, stale reply, lifecycle и ввод.
[Первичный протокол DBusMenu](https://cgit.arctica-project.org/libdbusmenu/plain/libdbusmenu-glib/dbus-menu.xml).

## Календарь панели

Кликните по часам, чтобы открыть календарь на текущем экране. Стрелки
переключают месяц и год. Кнопка «Сегодня» возвращает локальную дату.
Escape и клик вне календаря закрывают его. Часы показывают локальное
время, а подписи GTK используют локаль сеанса.

## Переполнение трея

Если значки трея не помещаются, кнопка «Ещё значки» открывает
прокручиваемый список. Клик, прокрутка и DBusMenu доступны и для
скрытых значков. При изменении ширины экран пересчитывает число
видимых значков. Для часов и настроек резервируется место.

## Раскладка верхней панели

В окне «Настройки Mosaic» откройте раздел «Верхняя панель». Стрелки
меняют положение элемента слева направо. Строка «Свободное место»
разделяет группы у краёв. Флажки управляют показом имени активного окна,
строки состояния и трея. Кнопка восстановления возвращает исходный порядок
и видимость. Изменения сохраняются и сразу видны на всех мониторах.

В конфигурации схемы 2 раздел выглядит так:

```toml
[panel]
order = ["menu", "active", "status", "spacer", "tray", "clock", "settings"]
hidden = []
```

Старый файл без раздела использует эту раскладку. В `order` каждый
элемент должен быть ровно один раз. В `hidden` допустимы `active`,
`status` и `tray`. Например, для скрытия имени окна и строки состояния:

```sh
./shellctl config set 'panel.hidden=["active","status"]'
```

## Положение Dock

В настройках Mosaic поле «Положение Dock» предлагает нижний, левый
и правый края. Смена применяется сразу. Сбоку список прокручивается
вертикально, увеличение направлено внутрь экрана, а меню и карточки
открываются рядом с Dock. Автоскрытие использует выбранный край.

```sh
./shellctl config set 'dock.edge="left"'
./shellctl config set 'dock.edge="right"'
./shellctl config set 'dock.edge="bottom"'
```

Файл без `dock.edge` сохраняет нижнее положение по умолчанию.

## Закрепление ярлыка из файлового менеджера

Перетащите один локальный `.desktop` установленного приложения в Dock.
Сброс над закреплённым значком вставляет ярлык перед ним. Сброс на
свободном месте добавляет его в конец. Повторный сброс сохраняет
существующее положение. Запись использует Desktop ID из каталога GIO,
загруженного при запуске оболочки. Исходный файл остаётся на месте,
а приложение можно запустить отдельным кликом.

Поддерживаются пути к эффективному ярлыку из каталога и ссылки на тот же
файл с тем же именем. Самостоятельно созданную копию сначала установите
как приложение пользователя и перезапустите Mosaic, чтобы обновить каталог.
В декларативной конфигурации закрепления задаются через `pins`.

## Корзина в Dock

Клик по кнопке открывает `trash:///` в обработчике GIO. Значок и
подсказка обновляются при изменениях. При недоступном GVfs подсказка
показывает, что корзина недоступна. Правый клик по непустой корзине
открывает подтверждение очистки. То же действие выполняет Shift+F10
на кнопке корзины. Escape или «Отмена» закрывает подтверждение.

`./shellctl trash status` показывает `empty`, `full`, `unavailable`
или `clearing`.
